# Database agent handoff

Created migrations `20261014000100_bank_schema.sql` and `20261014000200_bank_rpcs.sql`, integration tests `supabase/tests/bank.integration.mjs` and `bank.concurrent.mjs`, read-only `supabase/inspect/preflight.sql`, and `docs/DATABASE.md`. No live database was touched. `psql` is absent and Docker daemon is unavailable in this environment. Root should run preflight against the actual project, then review/run both migrations in a preview database before any production application.

Contract changes communicated to root: add `bank_set_urgent_opt_in(p_enabled boolean)`, `bank_donate(p_minutes,p_note,p_request_id uuid)`, and `bank_contribute_project(p_project_id,p_minutes,p_note,p_request_id uuid)` with stable request UUIDs. Read RPCs `bank_project_summaries()` and `bank_account_summary()` return exact project and owner-only wallet totals; root loader should consume them. `exchanges.initiator_id` identifies the member who sent a request; the other member accepts. Legacy documented `time_credits` exchange tables are renamed to `legacy_exchanges`, retained with old transactions, and client access revoked. Historical exchange migration needs a separate reviewed reconciliation decision because the old design has mutable credits and may already contain transfers.

Security review focus: execute grants on every `bank_*` function, profile column grants, legacy function revocation, and concurrency behavior of simultaneous exchange confirmations and fund decisions. `node supabase/tests/bank.integration.mjs` passed locally after PGlite installation. It executes the read-only preflight both before and after migration, then checks legacy table preservation, orphan auth-user backfill, exact opening and welcome entries, profile/account grants and RLS (including a seeded old column grant), confirmation checks, participant privacy, both offer and want exchanges, reservation-aware donation, cancellation release, completion settlement, idempotent donation/contribution, facilitator-only approval and no self-approval, urgent opt-in, exact project summaries, direct-RPC validation, and public summary counts. `bank.concurrent.mjs` passed on a disposable local PostgreSQL 18.4 cluster: simultaneous 90-minute acceptances against 120 minutes allowed one reservation, donation could not spend reserved funds, cancellation released the hold, later acceptance and settlement succeeded, and simultaneous confirmation produced one ledger pair. The cluster was started on localhost:55437 and stopped after the test. Its pinned binary package `@embedded-postgres/darwin-arm64@18.4.0-beta.17` was installed only under `/private/tmp/bank-postgres-runtime`; the root package was not changed. No production or preview Supabase database was touched.
